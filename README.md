| `kttf-minio` | файлы: фото игроков (ADR-036), логотипы клубов | `9000`, консоль `9001` |# kttf-infra

Инфраструктура KTTF: описание стека, обратный прокси, конфигурация сервисов.

Оркеструет **оба приложения сразу**, поэтому лежит отдельно и не принадлежит ни `kttf-back`, ни `kttf-front`. Обоснование — `kttf-shared/docs/06-decisions.md`, ADR-012.

## Быстрый старт

Нужны Git и Docker Desktop. Репозитории клонируются **рядом, в одну папку**:
стек собирает образы из соседних `../kttf-back` и `../kttf-front`.

```
mkdir kttf && cd kttf
git clone https://github.com/goats-web-studio/kttf-back.git
git clone https://github.com/goats-web-studio/kttf-front.git
git clone https://github.com/goats-web-studio/kttf-infra.git
git clone https://github.com/goats-web-studio/kttf-shared.git   # документация и общий код,
                                                                 # стеку не нужен

cd kttf-infra
cp .env.example .env          # локально можно оставить как есть; пароль
                              # Postgres — только вместе с kttf-back/.env.example
docker compose up -d --build  # первая сборка — минут 5–10
docker compose ps             # дождаться healthy у kttf-api
```

Открыть `https://localhost`. Сертификат Caddy выпускает сам и локально он
самоподписанный — браузер об этом предупредит.

Если порты 80 или 443 заняты, поменять `HTTP_PORT` / `HTTPS_PORT` в `.env`.

### Демо-данные

С `KTTF_DEMO_SEED=1` (так в `.env.example`) пустой стек при первом запуске
заполняется снимком из `seed/`: клубы, игроки, тренеры, турниры с
рейтингом, дуэли, форум, лента и каталог из 429 позиций. Делают это два
разовых контейнера: `kttf-seed` — база, до миграций; `kttf-seed-media` — файлы
в MinIO, до API. Непустую базу они не трогают, повторный `up` безопасен.

| Логин | Пароль | Кто |
|---|---|---|
| `owner` | `Owner2026!` | владелец клуба «KTTF Тест» и администратор платформы |
| `organizer` | `Organizer2026!` | организатор того же клуба |
| `player` | `Player2026!` | обычный игрок |

Ещё есть тренеры `coach1`…`coach6`. Пароль любому аккаунту задаёт
`pnpm build && pnpm set-password <логин> <пароль>` в `kttf-back` (нужен
его `.env` с `DATABASE_URL` на `localhost:5433`).

**Фото каталога** в репозиторий не входят: это 60 МБ снимков с RTTF. Без них
каталог открывается с заглушками. Чтобы были фото, распаковать архив
`kttf-catalog-photos-*.tar.gz` в `seed/media/` (получится
`seed/media/products/…`) и выполнить `docker compose up -d kttf-seed-media`.
Папка под гитигнором.

**Начать с чистого снимка** — `docker compose down -v`, затем снова
`docker compose up -d`. Всё, что накоплено в локальной базе, пропадёт.

**Обновить снимок** с текущей локальной базы:

```
docker exec kttf-postgres pg_dump -U kttf -d kttf --no-owner --no-privileges | gzip -9 > seed/demo.sql.gz
```

Перед коммитом вычистить личное: настоящие почты, телефоны, Telegram и
таблицу `Session`. Репозиторий публичный.

**В проде** `KTTF_DEMO_SEED=0`: демо-аккаунты с известными паролями там не
нужны.

Схему накатывает контейнер `kttf-migrate`: он отрабатывает `prisma migrate
deploy` и завершается, API стартует только после него (ADR-030). Отдельного
шага у человека не осталось.

**Вход — логин и пароль** (ADR-034). Одноразовых кодов и провайдера SMS у
продукта больше нет: как войти на пустой базе, написано в
`kttf-shared/docs/05-state.md`.

## Что и где

| Контейнер | Роль | Порт на хосте |
|---|---|---|
| `kttf-postgres` | PostgreSQL 17 | `5433` |
| `kttf-redis` | кэш и очереди BullMQ | `6380` |
| `kttf-minio` | файлы: фото игроков, логотипы клубов | `9000`, консоль `9001` |
| `kttf-seed`, `kttf-seed-media` | разовая заливка демо-данных в пустой стек | — |
| `kttf-migrate` | разовая миграция схемы, отрабатывает и завершается | — |
| `kttf-api` | NestJS | внутренний |
| `kttf-web` | статика React на Caddy | внутренний |
| `kttf-proxy` | Caddy, единственная точка входа | `80`, `443` |

Всё в одной сети **`kttf-net`**, подсеть `172.28.0.0/16`. Между собой сервисы обращаются по именам и штатным портам: `kttf-postgres:5432`, `kttf-redis:6379`, `kttf-minio:9000`. Смещённые порты хоста внутри сети роли не играют.

**Имя сервиса совпадает с именем контейнера.** Одна сущность — одно имя везде: во внутреннем DNS, в `docker ps` и в интерфейсе Docker Desktop. Иначе на каждый сервис приходится по два имени, и в списке контейнеров видно не то, что в строке подключения.

**Почему порты смещены.** На машине разработчика уже может стоять свой PostgreSQL на 5432 или Redis на 6379. Контейнер, конфликтующий с ними, выглядит как «база не поднялась», а на деле занят порт. Смещение убирает целый класс путаницы.

## Профили

По умолчанию поднимается **всё, из чего состоит продукт**. За профилем остаётся только наблюдаемость:

```
docker compose --profile observability up -d     # плюс Prometheus и Grafana
```

**Профиль `observability`** локально не нужен и только ест память. В проде обязателен — `kttf-shared/docs/03-tech-spec.md`, раздел 8.5.

## Образы приложений

Локально собираются из соседних папок (`../kttf-back`, `../kttf-front`) — репозитории лежат рядом. В проде тянутся из GHCR: бэкенд по тегу `API_TAG`, фронтенд по `WEB_TAG`. Собирает и публикует их CI репозиториев приложений, выкладывает `deploy/deploy.sh` — [DEPLOY.md](DEPLOY.md). Описание одно, источник разный.

`Dockerfile` бэкенда многостадийный: цель `runtime` несёт только `dist` и прод-зависимости, цель `migrator` — полный набор вместе с CLI Prisma. `compose.yaml` указывает `target` явно у обоих сервисов. Обоснование — ADR-030.

Пересобрать после правки приложения:

```
docker compose up -d --build
```

## Чего здесь намеренно нет

**Оверрайда для разработки.** Разработка идёт мимо стека: `pnpm dev` во фронтенде и `node dist/main.js` в бэкенде быстрее любой пересборки образа. Стек нужен, чтобы проверить продукт целиком, а не чтобы в нём писать код.

**Секретов.** `.env` под гитигнором, в репозитории только `.env.example` с заглушками. Бриф, запрет №9.

## Локаль базы

PostgreSQL инициализируется с `ru-RU` через ICU. Без этого сортировка фамилий получается машинной: «Ё» уезжает в конец алфавита, а регистр начинает влиять на порядок. В списке участников турнира это видно сразу.

Локаль задаётся **только при первом создании тома**. Если база уже создана, смена переменной ничего не изменит — нужно удалить том: `docker compose down -v`.

## Полная очистка

```
docker compose down -v
```

Удаляет контейнеры вместе с томами. База, файлы и очереди пропадут — команда для того и нужна, чтобы проверить, что схема разворачивается с нуля.
