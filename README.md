# kttf-infra

Инфраструктура KTTF: описание стека, обратный прокси, конфигурация сервисов.

Оркеструет **оба приложения сразу**, поэтому лежит отдельно и не принадлежит ни `kttf-back`, ни `kttf-front`. Обоснование — `kttf-shared/docs/06-decisions.md`, ADR-012.

## Быстрый старт

```
cp .env.example .env          # пароли MinIO и Grafana заменить, Postgres —
                              # только вместе с kttf-back/.env.example
docker compose up -d          # поднимет postgres, redis, minio
docker compose ps             # дождаться healthy у всех трёх
```

Затем в `kttf-back` накатить схему:

```
pnpm exec prisma migrate deploy
```

## Что и где

| Контейнер | Роль | Порт на хосте |
|---|---|---|
| `kttf-postgres` | PostgreSQL 17 | `5433` |
| `kttf-redis` | кэш и очереди BullMQ | `6380` |
| `kttf-minio` | файлы: фото игроков, логотипы клубов | `9000`, консоль `9001` |
| `kttf-api` | NestJS — профиль `apps` | внутренний |
| `kttf-web` | статика React — профиль `apps` | внутренний |
| `kttf-proxy` | Caddy, единственная точка входа | `80`, `443` |

Всё в одной сети **`kttf-net`**, подсеть `172.28.0.0/16`. Между собой сервисы обращаются по именам и штатным портам: `kttf-postgres:5432`, `kttf-redis:6379`, `kttf-minio:9000`. Смещённые порты хоста внутри сети роли не играют.

**Имя сервиса совпадает с именем контейнера.** Одна сущность — одно имя везде: во внутреннем DNS, в `docker ps` и в интерфейсе Docker Desktop. Иначе на каждый сервис приходится по два имени, и в списке контейнеров видно не то, что в строке подключения.

**Почему порты смещены.** На машине разработчика уже может стоять свой PostgreSQL на 5432 или Redis на 6379. Контейнер, конфликтующий с ними, выглядит как «база не поднялась», а на деле занят порт. Смещение убирает целый класс путаницы.

## Профили

По умолчанию поднимается только инфраструктура. Остальное — явно:

```
docker compose --profile apps up -d              # плюс api, web, прокси
docker compose --profile observability up -d     # плюс Prometheus и Grafana
```

**Профиль `apps` пока не работает:** `kttf-back` и `kttf-front` ещё не содержат приложений и `Dockerfile`. Когда появятся — убрать `profiles: [apps]` из `compose.yaml`, чтобы стек поднимался целиком одной командой.

**Профиль `observability`** локально не нужен и только ест память. В проде обязателен — `kttf-shared/docs/03-tech-spec.md`, раздел 8.5.

## Образы приложений

Локально собираются из соседних папок (`../kttf-back`, `../kttf-front`) — репозитории лежат рядом. В проде тянутся из GHCR по тегу `IMAGE_TAG`. Описание одно, источник разный.

## Чего здесь намеренно нет

**Оверрайда для разработки.** Он понадобится, когда появятся приложения: примонтировать исходники и включить горячую перезагрузку, чтобы правка одной строки не требовала пересборки образа. Писать его сейчас, не видя реальной структуры приложений, значит гадать.

**Секретов.** `.env` под гитигнором, в репозитории только `.env.example` с заглушками. Бриф, запрет №9.

## Локаль базы

PostgreSQL инициализируется с `ru-RU` через ICU. Без этого сортировка фамилий получается машинной: «Ё» уезжает в конец алфавита, а регистр начинает влиять на порядок. В списке участников турнира это видно сразу.

Локаль задаётся **только при первом создании тома**. Если база уже создана, смена переменной ничего не изменит — нужно удалить том: `docker compose down -v`.

## Полная очистка

```
docker compose down -v
```

Удаляет контейнеры вместе с томами. База, файлы и очереди пропадут — команда для того и нужна, чтобы проверить, что схема разворачивается с нуля.
